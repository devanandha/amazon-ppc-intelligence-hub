# Fixed-budget, held-out baseline validation — protocol (v5)

**Purpose:** Test *which synthetic advertising terms to defer for more conversion evidence* when all ranking policies have the **same fixed acquisition capacity**. The hypotheses and evaluated model are exploratory; this is **not a preregistered study** or empirical Amazon advertising evidence.

## Data generation and split

- Synthetic cohorts are generated by the v4 `misspecification_experiment.sample_cohort` function. Each term has historical clicks/orders, CPC, AOV, hidden conversion probability, optional drift, optionally missing attribution, and optionally hidden actual margin. Observational ranking only sees historical clicks/orders, CPC and AOV.
- Training: seeds **6000–6019**, 20 independent cohorts × 1,600 terms = **32,000 synthetic training terms** under the stationary reference environment. Training cohorts are used to select a shared Beta prior from four candidates using the historical-order-count beta-binomial marginal likelihood; and choose one hybrid rank weight from [0, .25, .50, .75, 1] using **training-only simulated regret** at a preselected 10% allocation rate. The training simulator knows latent outcomes; this does not imply an advertiser could learn the same parameters from ordinary observed reports.
- Test: seeds **12000–12029**, 30 disjoint cohorts × 1,600 terms = **48,000 simulated test terms per scenario**. Six named stress scenarios are fixed by the v4 generator; these stress scenarios are not six independently sampled real advertising populations. No test seed is used to pick prior or hybrid weight.
- **Primary budget:** exactly 10% of terms in each cohort; **sensitivity budgets:** 5% and 20%. All ranking policies are required to defer **exactly** the same number of terms (80, 160 or 320 per 1,600-term cohort). This isolates the **allocation/ranking** question. It is *not* a claim that forcing a deferral with negative value is a sensible operational policy.

## Competing rankings and common costs

1. Reproducible random allocation (random uniform priorities keyed only by test seed).
2. Fewest historical clicks first.
3. Posterior profitability uncertainty (probability closest to 50% that unit contribution is positive).
4. One-step Bayesian VOI: rank by model-implied gain in value from collecting ten more clicks, net of acquisition overhead.
5. Train-tuned convex ranking blend of VOI and uncertainty percentiles. Lambda selected only on training data; report if weight collapses to a comparator rather than claiming a novel extra strategy.

All methods share: immediate Bayesian SCALE/NEGATIVE action, 10 exploration clicks if selected, posterior Bayesian follow-up action, assumed contribution margin 25%, future horizon 100 clicks, exposure multiplier 1.25, fictional exploration overhead 2 per deferred term, the same v4 latent opportunities/outcomes per scenario/seed, and the same latent-oracle regret calculation.

Training picked one common prior; no policy uses true future conversion probability, actual unknown margin, or future observed conversions for **initial allocation**. Every selected term shares the same after-exploration inference. A true-oracle regret baseline uses hidden simulated outcomes solely during evaluation.

## Evaluation and reporting

- Per seed report mean economic regret (fictional monetary units per term), mean utility, realised defer rate. The preferred comparative statistic is **paired regret difference** (VOI minus other ranking) within each scenario/budget and random seed; negative favors VOI.
- A descriptive 95% half-width uses 1.96 × between-seed standard deviation / sqrt(30). The interval does **not** adjust for multiple scenario/method/budget comparisons, distribution misspecification, research selection or systematic modeling uncertainty; it is not a posterior credible interval or out-of-model validation.
- Also report **unconstrained** positive-net-VOI (deferral iff predicted net information value is positive) against immediate Bayes, explicitly separating this natural-policy diagnostic from fixed-rate comparisons. Their deferral rates differ, so never interpret them as matched-budget evidence.
- Report negative results and hybrid parameter selection, including if it duplicates an existing method.

## Threats to validity

- Bayesian VOI optimises a stylised economic model closely aligned to the evaluation objective; model-aligned success is partly expected and cannot demonstrate independent methodological novelty.
- No actual Amazon auction, spend pacing, placement auction effects, per-account structure, causal interventions, supplier constraints, inventory constraints, delayed conversions accurately calibrated to Amazon attribution, or real advertising profitability is modeled.
- Some scenarios are generated with a different latent distribution but share one broad family of synthetic economic equations. All comparisons are in-simulator, not externally validated.
- Forcing equal deferral counts is deliberately artificial. Rankings at q=5/10/20% are batch capacity-allocation questions, not necessarily the safest field decision policy. Real advertising action costs cannot be inferred from this simulator.
- The classifier's actions are only SCALE and NEGATIVE after deciding. An operational MAINTAIN action is unavailable, potentially exaggerating decision extremes.
- No independent reviewer has confirmed scientific novelty, and no seller has supplied independently authorised evaluation data for this extension.

## Reproduction

In the existing repository branch, place the incremental files included in this v5 ZIP into `research/bayesian_voi/`, then run:

```bash
cd research/bayesian_voi
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python fair_baselines.py
```

All six simulated scenarios are reused from the already published `misspecification_experiment.py`; the v5 release intentionally does not overwrite it or the live Streamlit app. Captured CSV results correspond to a Python 3.13.5 environment with NumPy 2.3.5, SciPy 1.17.0 and pandas 2.2.3; dependency ranges allow other versions and should not be called exact environment pinning.
